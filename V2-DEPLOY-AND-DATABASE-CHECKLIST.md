# AMBAR Furniture V2 — deployment and database checklist

This package preserves the existing customer storefront, checkout/order flows, favorites, profile/order tracking, custom orders, and ERP/admin pages. It refreshes the storefront styling to match the supplied furniture-shopping reference.

## Important: V2 only

Use this package only in the separate V2 GitHub repository, V2 Render service, and V2 Supabase project. Do not replace or modify the production bot or production database.

## 1. Render start settings

- Build command: `pip install -r requirements.txt`
- Start command: `python bot.py`
- Root directory: blank (repository root)

## 2. V2 Render environment variables

- `BOT_TOKEN`: token generated by BotFather for the bot that launches this Mini App. Enter privately in Render; never commit it to GitHub.
- `BOT_PUBLIC_USERNAME`: `AMBAR_SALESBOT` (without `@`)
- `WEBAPP_URL`: `https://ambar-furniture-dvit.onrender.com/` (replace only if your V2 Render URL differs)
- `SUPABASE_URL`: URL of the separate V2 Supabase project
- `SUPABASE_SECRET_KEY`: server-side secret for that same V2 project
- `SUPABASE_SERVICE_ROLE_KEY`: legacy service-role JWT if your project uses it; do not put an `sb_secret_...` value in this variable
- `ADMIN_PASSWORD_MANAGER_TELEGRAM_ID`: your numeric Telegram user ID
- `ADMIN_EMERGENCY_PASSWORD`: strong V2-only emergency password
- `SESSION_SIGNING_SECRET`: long random V2-only secret

The `/api/health` endpoint reports whether required environment variables are present. It never returns secret values:
`https://YOUR-V2-RENDER-URL/api/health`

## 3. Apply V2 database migrations

Open the SQL Editor in the separate V2 Supabase project and run these files, in order:

1. `ambar_v2_storefront_bootstrap.sql` — creates the `products` and `admin_security_events` tables confirmed missing in the supplied V2 Render logs, and the product image bucket.
2. `ambar_v2_customer_favorites_settings_migration.sql` — creates `customer_app_state`, `ambar_interface_settings`, and admin button settings.
3. `ambar_v2_approval_workflow_migration.sql` — creates approval/workflow structures included in this package.

Other ERP functions may require additional migrations referenced in `V2-INTEGRATION-GAP-REGISTER.md`; this package does not fabricate missing order, finance, or workshop schemas. Check that register before declaring the complete ERP database ready.

## 4. Telegram launch

- Configure the bot's Main Mini App / menu button to use the V2 Render URL.
- Open the Mini App from the `AMBAR_SALESBOT` private chat, not by pasting the Render URL into an ordinary browser.
- The private channel invite URL is not a numeric channel ID. `SERVICE_CHAT_ID` must be the channel's numeric ID (usually begins `-100`).

## 5. Authentication troubleshooting

The browser sends Telegram's raw `Telegram.WebApp.initData` to `/api/auth/me`. The server validates its HMAC using the V2 `BOT_TOKEN` and logs safe diagnostic reasons (missing token, missing initData, malformed payload, stale auth date, or HMAC mismatch). Never log or share the raw initData or bot token.

If `/api/health` says `telegram_bot_token_configured: false`, add the V2 bot token to Render. If Render logs say `HMAC mismatch`, the token configured on the V2 service does not belong to the bot that launched the Mini App. If logs say the initData header is missing, the app was not launched through Telegram's configured Mini App button or the Telegram Web App SDK did not provide launch data.

## Verification boundary

Local syntax and package-integrity checks do not prove that a live Telegram account, Render environment, Supabase project, Telegram menu button, or payment provider is configured correctly. Those require the owner's V2 credentials and live service access. This package does not deploy itself.
